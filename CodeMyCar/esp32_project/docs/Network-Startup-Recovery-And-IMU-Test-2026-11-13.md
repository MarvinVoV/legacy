## 修复

1. Wi-Fi初次连接和重连回调统一处理`esp_wifi_connect()`同步失败：不能只等待可能不会到来的DISCONNECTED事件。失败后继续指数退避，默认1s起、最长60s；配置0保持无限重试，计数饱和避免长期运行溢出，有限重试配置仍遵守上限。
2. Wi-Fi停止后拒绝迟到的STA_START/GOT_IP事件，避免重新触发连接或启动MQTT。已关联时不重复发起连接；跨任务状态使用C11原子变量。
3. MQTT区分“请求运行”和“SDK客户端已启动”，重复GOT_IP不再重复调用SDK start。正常断网仍由ESP-MQTT自身恢复。
4. 同步MQTT启动失败继续保留运行意图，每2秒定时重试，直到成功或显式stop；启动锁繁忙时不阻塞共享esp_timer任务，而是延期。停止/销毁取消待执行重试，重试基础设施初始化失败清理句柄。
5. Bridge检查MQTT启动返回值并明确记录失败和服务恢复机制，不再静默忽略。

不改运动命令、STOP、租约、串口帧、语音参数或STM32中位。不是新增Wi-Fi遥控运动开关；语音执行仍保持默认关闭。
