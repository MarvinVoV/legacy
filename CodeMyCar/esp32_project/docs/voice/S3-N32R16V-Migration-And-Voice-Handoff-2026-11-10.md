## 对原始方案的取舍

原文保存在同目录 `S3-Voice-Proposal-User-2026-11-10.md`，作为参考，不作为接线/验收依据。

- 保留三层：pyserver负责识别、会话和动作调度；S3负责网络/音频；STM32继续负责电机、编码器、IMU与运动安全。不把实时控制移到S3，也不以小智固件替换整个控制桥接。
- 本车为舵机连杆转向，不能套用差速底盘原地转十圈标定，也不能直接以左右轮转速差公式代替真实转向几何。
- 借鉴小智一个AFE、事件驱动、播放结束后再听音等设计。当前只接一只麦克风，关闭双麦SE/BSS；Mac没有同步播放参考，关闭AEC；AGC先关闭，避免盲目抬高噪声。
- 先实现“你好小智→提示音→一句话→百度ASR→Mac回读→待机”。保留严格运动意图及原有AgentMotionService；未配置的LLM/小智服务器/MCP不伪装成已完成。自由对话是后续有明确提供商配置时的独立功能。
- 自定义WakeNet需对应训练模型；小智的拼音自定义路径是MultiNet方案，不能混为一谈。首版用现成WakeNet9“你好小智”。
- NS4150B模拟功放不能仅靠I²S直接播放；未来板的DAC/codec和参考通道需看原理图。INA219改址、传感器5V电平、I²C地址与避障策略不能直接照搬原文。现有STM32避障的近场快判也不应被“所有单次异常均忽略”的统一中值策略覆盖。

## 编译与分区

在ESP-IDF6.1环境中，从仓库CodeMyCar目录执行：

```sh
python esp32_project/tools/firmware.py build
python esp32_project/tools/firmware.py --port /dev/cu.usbserial-110 flash
python esp32_project/tools/firmware.py --port /dev/cu.usbserial-110 monitor
# 只构建旧C6，不烧录到S3：
python esp32_project/tools/firmware.py --board c6 build
```

脚本默认S3，使用 `build-s3/` 和忽略入库的 `sdkconfig.s3`；旧 `build/` 与 `sdkconfig` 保留给C6。已删除顶层CMake对构建目录的强制覆盖，避免 `-B` 失效。不要对旧C6树直接运行 `set-target esp32s3`，也不要把S3镜像刷到C6。

S3配置叠加 `sdkconfig.defaults` 与 `profiles/s3-n32r16v.defaults`：双核240MHz；Octal Flash、DTR、80MHz；Octal PSRAM 80MHz并执行启动内存测试。保持默认UART控制台，当前连接的是板上标注UART的USB口；原生USB GPIO19/20不作音频引脚。WROOM-2占用的35/36/37也不接外设。

`partitions_s3.csv`：NVS/PHY保持原偏移；factory从0x10000开始6MB；model从0x610000开始4MB。其余Flash预留，当前未实现OTA或多媒体文件系统；不能把预留空间当成已有OTA支持。大Flash是容量提升，不直接提高推理速度。

## 当前拾音接线（需断电操作）

| 模块麦克风侧 | S3 |
|---|---|
| VCC | 5V（按用户确认的整板说明书） |
| GND | GND |
| SCK | GPIO12 |
| WS | GPIO13 |
| SD | GPIO14输入 |

功放侧DIN/BCLK/LRCLK暂不接，不把其DIN当成麦克风SD。I²S信号逻辑电平仍须符合3.3V GPIO要求。16kHz、32bit stereo slot，默认取左槽高16位；若模组声道选择不同，通过 `CMCAR_VOICE_I2S_RIGHT_CHANNEL` 改，不以随意加大增益掩盖错误槽位。SD启用弱下拉，避免未接线和未驱动槽浮空。

STM32 UART接线已于2026-11-11按两端代码核对（实物通信验收仍待完成）：

| ESP32-S3 | STM32 | 方向 |
|---|---|---|
| GPIO4 / UART1 TX | PA11 / UART4 RX | S3→STM32 |
| GPIO5 / UART1 RX | PA12 / UART4 TX | STM32→S3 |
| GND | GND | 共地 |

STM32的 `Application/Modules/UART/Src/uart_handle.c` 使用huart4，`Core/Src/stm32h7xx_hal_msp.c` 定义PA11=RX、PA12=TX；两端均115200、8N1、无硬件流控。PA11/PA12是GPIO名，不是排针物理序号。S3使用排针4/5，不是板上下载调试的TX/RX串口。

断电接线；当前验收两板各自USB供电，只连上述三根线，不互接5V或3V3，也不接旧C6。后续需要STM32给S3供电时，再单独核对5V电源能力与USB供电路径。

## 内存与任务分配

| 项目 | S3配置 | 位置/理由 |
|---|---|---|
| UART驱动RX / TX | 4096 / 1024字节 | 内部RAM，承受日志/遥测突发 |
| UART原始RingBuf | 4096字节 | 内部静态内存 |
| UART TX队列 | 16帧 | 有界内部队列，原C6为8 |
| MQTT缓冲 | 4096字节 | 比C6默认2048适度增加；不引入无界outbox |
| 音频处理后队列 | 64×648=41472字节，约1.28秒 | PSRAM显式分配；控制结构在内部RAM；满时替换最旧帧，上传检测序号缺口并中止 |
| I²S读取临时区 / PCM临时区 | 2560 / 640字节 | 显式内部RAM；I²S区具有DMA能力 |
| AFE输入拼帧区 | 按库查询，当前512样本约1024字节 | 内部RAM；不是假设上传320样本就等于模型帧 |
| AFE模型工作区 | `AFE_MEMORY_ALLOC_MORE_PSRAM` | 库自行分配合适能力内存，不承诺全部外移 |
| 语音上传 / WebSocket / 采集 / AFE输出栈 | 8192 / 6144 / 4096 / 6144字节 | 任务栈保持内部RAM；后续看实际高水位调整 |
| 内部RAM分配保护 | malloc≤16KB优先内部；预留64KB | 不让大块音频缓存挤占驱动和任务资源 |
| 其他控制队列 | 保留原有界大小 | 命令排队变长会积压旧指令，不能因内存富裕无限增加 |

健康监控改看内部8bit RAM及其最低水位，不能让16MB PSRAM掩盖内部内存耗尽。待机诊断分别打印内部RAM、PSRAM和语音任务栈余量。未将剩余PSRAM预分配为巨大缓存，留给后续播放、多媒体、TLS及网络。

## 音频架构与C6定制的处理

S3：采集任务单独读I²S→单个常驻AFE→独立fetch输出任务→重组320样本/20ms帧→有界PSRAM队列→会话/网络任务。AFE工作在core1、优先级3；采集/网络低于UART和桥接的任务优先级。没有把网络请求放进采音回调。I²S启动前检查输入/输出能力、三信号互斥、与控制UART冲突，以及WROOM-2存储引脚冲突。

旧C6的独立WakeNet9s适配保留在 `voice_wake.c`，S3不编译它。S3模型分区选择WakeNet9+VadNet1及可选NSNet2；**当前默认关闭实验NS**，禁用AEC、SE和AGC。首轮启用NS时“前进一米”被识别成“将近一米”，库本身也提示NS可能损伤识别，因此先做关闭NS的对照，不能未经验收就认定开得越多越好。启用实验开关时，待机旁路NS、听音时开启。算法控制由fetch任务单独应用；不在每次唤醒时clean或销毁重建模型。S3启用双核后，触发/忙碌状态使用C11原子变量，避免继续依赖volatile跨核同步。

上行保持PCM，服务端仍负责端点切分，连续送处理后音频而不是仅送VAD=true的片段，以免剪掉首尾字。唤醒前不上传；单次唤醒只处理一句；结束需等实际Mac播放完成，冷却期间保持忙碌、丢弃旧队列，不因播报再次触发。

真实测试额外发现并修复：旧20秒听音窗口将云请求时间一起计入，慢网络下会取消已收齐的句子。现在服务端端点形成后立即发 `recognizing`，客户端停止上传发end，另用45秒上限等待识别/播报完成。15秒结果新鲜度限制仍由服务端保留，避免迟到的运动指令执行。Mac提示音改250ms/幅值8000，播放器非零退出码不再静默忽略。

语音初始化失败有明确错误返回，main记录降级并继续运行控制桥接，不因音频失败让整车反复重启。硬件不接麦克风时无法认证语音效果。
