一、项目定位与整体架构
1.1 项目目标
打造一台具备躯体与智能的桌面级语音交互小车：
• 语音唤醒 → 对话交互 → 指令执行（前进/后退/转向）；
• 具备基本环境感知（避障、距离检测）与自身状态感知（位移、姿态、电量）；
• 智能层走云端大模型，设备端保持“薄”，逻辑可远程迭代。
1.2 技术架构：与宇树 Go2 同构的“云端大脑 + 本地小脑”
机器人系统的标准姿势是分层计算、各司其职，本项目采用与商用机器人一致的分层思路：
┌─────────────────────────────────────────┐
│  云端（大脑）：ASR / LLM 对话 / TTS       │  ← 智能在云端，改提示词不烧固件
├─────────────────────────────────────────┤
│  ESP32-S3（小脑）：                       │
│   · 唤醒词检测（离线，ESP-SR WakeNet）    │
│   · 音频采集/播放 + AFE 降噪/AEC          │
│   · 电机实时控制 + 传感器采集             │
│   · Wi-Fi 通信（WebSocket / MQTT+UDP）   │
├─────────────────────────────────────────┤
│  传感器层（五官）：                       │
│   编码器(位移) · 九轴IMU(姿态) ·          │
│   超声波(避障) · INA219(电量) · OLED(显示)│
└─────────────────────────────────────────┘

2.3 I2C 总线地址分配表（关键！曾踩坑）
设备	地址	备注
OLED (SSD1306)	0x3C
IMU (MPU9250)	0x68

ES7210	0x40	音频 ADC，保持默认
2.4 超声波模块接线注意事项
• Trig → 任意空闲 GPIO（ESP32 直驱）；
• Echo → 老版 HC-SR04 输出 5V，需 1kΩ+2kΩ 分压至 3.3V 再接入，否则损伤引脚；HC-SR04P/JSN-SR04T 支持直连，看板子丝印确认；
• 占 2 个 GPIO，不占 I2C；
• 安装：离地 ≥10cm，朝前微仰 5~10°，避免 30° 锥形波束扫到地面误触发。
三、里程计与定位方案
3.1 精度预期（现实主义）
任务	需求	本方案能否满足
语音指令“前进 50cm / 转 180°”	相对误差 <5%	✅ 绰绰有余
自主漫游不撞墙	避障即可	✅ 超声波负责
回到出发点（10m 内）	闭环误差 <30cm	⚠️ 可达，需标定+限速
定点停靠（充电对接）	<3cm	❌ 需加 UWB 或信标
3.2 差速底盘里程计公式与误差来源
v = (vL + vR) / 2        // 航速 = 两轮平均
ω = (vR - vL) / track    // 角速度 = 两轮差速 / 轮距
误差三大来源：打滑（编码器测的是轮转不是车动）、track 参数不准（轮胎软硬、地面材质会改变有效值）、差速转弯的固有侧滑（结构性，无法消除）。
3.3 标定流程（到手后第一件事，20 分钟，精度差三倍）
1. 直线标定：指令走 1m，卷尺实测，反算轮径修正系数；
2. 旋转标定：原地转 10 圈，实测总角度，反算 track 修正系数；
3. 将修正系数写入固件常量。
3.4 软件要点
• 编码器用 GPIO 中断 + ISR 累加计数，主循环 10~20ms 读一次清零（轮询会漏脉冲）；
• IMU 陀螺仪积分管短时航向，磁力计仅在电机静止时校准（电机磁场干扰）；
• 转弯速度 ≤0.3 转/秒，缓起缓停，压住打滑。
3.5 未来升级路径（按成本）
1. 红外/编码信标 + 超声波 → ±5cm 停靠（回充够用）；
2. UWB（DW3000 模块，¥40~80/对） → 室内 10~30cm 绝对定位，与 ESP32-S3 生态兼容（Makerfabs ESP32 UWB 板即 S3 主控）；
3. 视觉 SLAM → 厘米级，需树莓派/Jetson 级算力（远期）。
四、软件方案：基于 xiaozhi-esp32 裁剪开发
核心策略：不重写，而是 fork 裁剪。 xiaozhi-esp32（MIT 协议，~2.5 万 stars）专为“ESP32-S3 + 双麦 + 云端大模型”链路设计，Opus 编解码、I2S 双工、AEC 参考信号、板级抽象等坑它都踩过了。
4.1 架构借鉴
xiaozhi 的关键设计：设备端薄（唤醒 + Opus 编码 + 传输），逻辑全在服务端。好处：改提示词/对话逻辑不用重烧固件。
4.2 四大目标实现方案
#	功能	难度	实现路径
1	自定义唤醒词	⭐⭐	ESP-IDF menuconfig → 从 ~26 个乐鑫官方免费唤醒词中选；完全自定义词走 USE_CUSTOM_WAKE_WORD（拼音 + 阈值 15~20%），需 WakeNet 训练工具。换词后 idf.py fullclean 再编译
2	云端 ASR/TTS 对接	⭐⭐	自建 xinnan-tech/xiaozhi-esp32-server（Python），改配置对接自己的 ASR/LLM/TTS API 密钥，设备固件一行不改
3	语音打断（barge-in）	⭐⭐⭐⭐	NS4150B 为模拟功放无数字回采 → 走软件 AEC + 虚拟参考信号路线（参考社区 PR #462）：播放时建缓存，采音时写入参考通道；AEC 模式 AEC_MODE_VOIP_HIGH_PERF；播放采样率统一 16kHz；播放与采集时间同步需 ±60ms 内
4	降噪优化	⭐⭐⭐	ESP32-S3 AFE 引擎：NS + AGC + BSS（双麦波束成形）+ VAD。唤醒环节关 NS（社区实测 NS 降唤醒率），仅对话环节开。硬件层面：电机电源加去耦电容、麦克风远离电机布置
4.3 板级适配（fork 后第一件正事）
在 main/boards/ 下参照 ESP-BOX-3（同为 ES7210 输入）建自己的板目录，把 I2S/I2C/电机引脚改为实际接线。
4.4 MCP 工具注册：打通“语音 → 电机”
把运动控制注册为 MCP 工具，云端 LLM 解析意图后直接调用：
// 伪代码示意
MCP.AddTool("self.car.forward",  "前进", {"distance_cm": "int"}, ...);
MCP.AddTool("self.car.turn",     "转向", {"angle_deg": "int"}, ...);
MCP.AddTool("self.car.stop",     "停止", {}, ...);
效果：直接说“往前走一点”→ 大模型解析 → 调用 car.forward → 电机转。无需手写指令词表。
4.5 安全层设计（优先级高于一切语音指令）
超声波 < 10cm  → 无条件刹停（电机控制循环内硬规则）
超声波 10~25cm → 减速 50%
语音"前进"     → 受上述规则约束
超声波读数做滑窗中值滤波（5 次取中值），单次异常不触发刹车。

六、知识储备存档（概念科普）
6.1 机器人“大脑”选型速查
平台	角色	本项目取舍
ESP32-S3	实时控制 + 音频前端 + 轻量 AI	✅ 主体，不换
STM32	高实时电机闭环	加机械臂时做“小脑”
树莓派 5	Linux + ROS/SLAM 中层大脑	需视觉导航时引入
Jetson Orin	边缘 AI/本地大模型	商业级需求才上
原则：智能放云端则设备算力需求极低；机器人系统正确姿势是板子各司其职，而非一块板包打天下。
6.2 WBC（Whole-Body Control）全身控制
人形机器人“小脑算法”：把全部关节、接触约束、任务目标放进同一个 QP 优化问题，500~1000Hz 求解关节力矩。典型架构为 MPC（规划动量）+ WBC（落成力矩）。轮式小车不涉及，做人形/机械臂时绕不开。
6.3 力传感器
• FSR 薄膜（¥5~20）：单方向粗检测，DIY 夹爪够用；
• 六维力/力矩（¥3000+）：人形腕/踝标配；
• 低成本替代：关节电机电流环反推力矩。
6.4 UWB 超宽带定位
纳秒级窄脉冲测飞行时间，室内 10~30cm 精度（AirTag 同款技术）。入门玩法为 TWR 双向测距（两板互测距离，无需时钟同步）；TDoA 多锚点定位需纳秒级同步，新手勿碰。
6.5 传感器融合核心原则
最好的融合不是同类传感器投票，而是异类传感器互相补盲——本项目的“编码器（位移）+ IMU（姿态）+ 超声波（环境）”三角即此原则的落地。
