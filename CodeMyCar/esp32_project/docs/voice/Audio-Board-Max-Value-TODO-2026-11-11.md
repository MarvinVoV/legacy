## 阶段 A：硬件 bring-up 与声学基线（P0）

> 目标：先证明板子能安全供电、能被 I2C 找到、能出声、能双麦采集，并确认是否存在 AEC 参考。

- [ ] **A1 板子信息归档**
  - 记录型号/商品链接/丝印/照片；
  - 标出 VCC、GND、SDA、SCL、MCK、BCK、WS、DI、DO、EN；
  - 记录喇叭阻抗/功率、麦克风数量/位置；
  - 验收：文档中有照片/表格，无歧义。
  - 依赖：用户提供板子照片/链接。

- [ ] **A2 电源与 3.3V 检查**
  - 仅接 VCC 5V/GND，测板载 3.3V、空载/播放电流；
  - 确认 I2C/I2S 逻辑为 3.3V，I2C 上拉不被拉到 5V；
  - 验收：3.3V 在 codec 允许范围；无异常发热/掉压。
  - 风险：板子若无 LDO，禁止 5V 直接进 codec。

- [ ] **A3 I2C 扫描与 codec 识别**
  - 接 SDA/SCL，扫描地址；
  - 读 ES7210/ES8311 芯片 ID/版本；
  - 记录地址、复位/EN 脚状态；
  - 验收：两个 codec 都能稳定识别，重复上电一致。

- [ ] **A4 I2S 时钟与 ES8311 出声**
  - S3 I2S master：MCK/BCK/WS；S3 DOUT → 板 DI；
  - 配置 ES8311 DAC，小音量播放 1 kHz tone；
  - EN 高电平打开 NS4150B；先小音量；
  - 验收：喇叭有稳定 tone，无爆音/明显失真；EN 低电平静音。

- [ ] **A5 音量/静音/EN 时序**
  - 实现 ES8311 音量、mute，NS4150B EN GPIO 时序；
  - 上电先静音，codec 初始化完成后再开 EN；关机先 EN 低；
  - 验收：连续开关 20 次无爆音；音量档位可重复。
  - 代码：`voice_codec_board.c`（输出部分）。

- [ ] **A6 ES7210 双麦采集**
  - S3 DIN ← 板 DO；配置 ES7210 2 通道/TDM；
  - 记录每个通道的 RMS/峰值/底噪，确认左右麦映射；
  - 遮盖单麦，确认通道对应关系；
  - 验收：双通道独立、无串扰；语音 RMS 在合理范围，不削顶。
  - 代码：`voice_codec_board.c`（输入部分）。

- [ ] **A7 AEC 参考探测（audio_loopback_probe）**
  - 独立 probe：ES8311 播放 tone/chirp，ES7210 录 2/4 通道；
  - 遮麦、开麦、EN 低/高、喇叭断开分别录音；
  - 对播放信号与各通道做互相关；
  - 输出：每个通道「电气回采 / 声学拾取 / 无信号」结论；
  - 验收：明确是否存在硬件参考通道；WAV 和脚本结果归档。
  - 依赖：A4/A6；详见板子分析文档第 5 节。

- [ ] **A8 声学基线（当前 vs 新板）**
  - 测 SNR、底噪、频响、最大不削顶音量、THD（可用简单 FFT/录音）；
  - 1 m / 3 m、安静/风扇/电机噪声；
  - 与当前 ICS43434 方案做 A/B；
  - 验收：有量化表，不用“感觉更好”。

- [ ] **A9 板级稳定性**
  - 5V 供电、USB 供电、功放峰值、WiFi 并发；
  - 30 分钟播放/采集；看复位、掉压、I2C 错误、发热；
  - 验收：无异常复位/掉线；记录电流和温度。

**阶段 A 出口条件：** 能稳定出声、双麦采集、明确 AEC 参考结论、有量化声学基线。

## 阶段 B：本地体验与设备端音频（P1）

> 目标：让用户马上感受到“唤醒有回应、回答从车上来”，不依赖电脑发声。

- [ ] **B1 `voice_codec_board.c` 正式实现**
  - 输入：ES7210；输出：ES8311；参考：按 A7 结论；
  - 音量/静音/EN；错误处理；初始化失败不影响控制桥；
  - 验收：A2–A6 的测试用例在正式 codec 路径复跑通过。

- [ ] **B2 本地唤醒应答“我在”**
  - 预录 16 kHz/16-bit/mono PCM，16–26 KB；
  - `voice_wake_ack.c/.h`；唤醒后本地播放；
  - 第一版：播放完成 → flush 麦克风 → 再建立 conversation；
  - 验收：断网唤醒可听“我在”；服务端没有“我在”的 ASR 文本；10 次无爆音/卡顿。
  - 依赖：A4/A5。

- [ ] **B3 设备端 TTS 输出**
  - pyserver `speak` 1 KB 分片 → S3 重组 → `voice_output` → ES8311；
  - 播放排空/队列下溢/过载策略；
  - 验收：长 TTS 不再断连；音画/文本顺序正确；无爆音。

- [ ] **B4 音量/夜间模式/保护**
  - 音量曲线、最大音量限制、喇叭保护、夜间低音量；
  - 验收：最小/最大音量无爆音；长时间高音量不过热。

- [ ] **B5 双麦 AFE 接入**
  - 若 ESP-SR 支持双麦：AFE 双通道配置；否则明确单麦路径；
  - 保留无 AGC/无增益补丁原则；
  - 验收：双麦唤醒率/ASR 与单麦 A/B 数据。
  - 依赖：A6。

- [ ] **B6 本地提示音资源管理**
  - 固定提示音表（我在/请说/网络异常等）；
  - Flash/分区/资源更新策略；
  - 验收：不挤占应用分区；可单独更新资源。

- [ ] **B7 诊断与可观测性**
  - 每通道 RMS/峰值、AEC 状态、参考电平、削顶、I2C 错误、播放欠载；
  - 通过日志/心跳/调试接口输出；
  - 验收：出现音频问题时能定位到输入/输出/参考/网络。

**阶段 B 出口条件：** 新板可独立完成唤醒提示、ASR 上行、TTS 下行；电脑可不发声。

## 阶段 C：AEC、全双工与实时打断（P2，最高差异化）

> 目标：从半双工升级到可靠全双工；没有参考就停在这里，不虚假宣传。

- [ ] **C1 参考通道接入 AFE**
  - 按 A7：硬件参考或软件参考；
  - AFE `mic + reference` 配置；AEC on；
  - 处理参考延迟/时钟/幅度；
  - 验收：ERLE、双讲、残余回声有量化数据。

- [ ] **C2 AEC 参数与延迟对齐**
  - 参考延迟扫描、AEC 收敛、非线性残余；
  - 不同音量/喇叭/麦克风距离；
  - 验收：AEC 开启明显降低回声；不吞用户语音。

- [ ] **C3 全双工会话状态机**
  - TTS 播放期间保留麦克风检测；
  - 用户开口 → 停止/取消 LLM+TTS → 回到 listening；
  - 半双工/全双工可配置切换；
  - 验收：打断延迟、误打断率、TTS 不中断正常轮次。

- [ ] **C4 `barge_in` 协议与输出清队列**
  - S3 本地 VAD/AEC 触发 `barge_in`；
  - pyserver 取消 LLM/TTS；S3 `voice_output_stop` 清队列；
  - 验收：打断后无残留 TTS、下一句可识别。

- [ ] **C5 双讲/回声压力测试**
  - 用户与 TTS 同时说话；不同音量/距离；
  - 误打断率/漏打断率；
  - 验收：达到预设阈值；否则保持半双工。

- [ ] **C6 无参考 fallback**
  - A7 证明无硬件参考时，实现/验证软件参考；
  - 仍不达标 → 固定半双工，文档明确；
  - 验收：不把“AEC 商品页”当成功能完成。

**阶段 C 出口条件：** 真实车载/桌面环境可打断，且 AEC 数据达标；否则 C 不标完成。

## 2026-11-12 实测进展

- **A2/A3 通过**：5V/3.3V 正常；I2C 扫描到 ES8311 `0x18`、ES7210 `0x41`（7-bit）。
- **A4 基本通过**：ES8311 + NS4150B 可播放 1 kHz tone；确认该板 DI/DO 是 **ESP32 视角**：DO→GPIO18（S3 DOUT），DI→GPIO21（S3 DIN）。

- 下一步 **A7**：配置 ES7210 4ch/TDM 或确认 MIC3/参考回采；同时播放 tone 并录各通道，判断是否存在硬件 AEC 参考。未确认前不进入全双工/打断。
