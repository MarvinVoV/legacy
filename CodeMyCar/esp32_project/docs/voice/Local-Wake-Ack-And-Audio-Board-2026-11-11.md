# 本地唤醒应答与 ES7210/ES8311/NS4150B 音频板分析

**日期：** 2026-11-11  
**状态：** 方案设计，未接入新板；当前 S3 仍没有功放输出，`voice_output` 为 no-op。  
**目标：** 唤醒词命中后，ESP32 本地立即播放“我在”，不访问网络；同时为 ES7210 + ES8311 + NS4150B 音频板给出接线、AEC 和软件接入方案。

---

## 1. 本地唤醒应答“我在”

### 1.1 需求

- WakeNet 检测到“你好小智”后，ESP32 本机输出一句“我在”；
- 不调用百度 TTS、不经过 pyserver、不依赖 Wi-Fi；
- 提示音不能污染后续 ASR，不能把“我在”当作车主说的话；
- 未来可扩展成多条本地提示音，但第一版只做固定短句。

### 1.2 方案对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 预录 PCM 提示音 | 零网络、启动快、音色固定、实现简单 | 换词需重新生成资源 | **首选** |
| 预录 Opus/ADPCM | Flash 更小 | 需解码、增加 CPU/复杂性 | 32MB Flash 无必要 |
| 运行时 `esp_tts` | 可动态生成任意短句 | 模型/Flash/CPU 开销大，首声延迟高 | 只有需要任意短句时才用 |
| 纯提示音/双音 | 最简单 | 不是“我在” | 可作为辅助提示 |

### 1.3 推荐实现

1. 用百度 TTS（同一精品音色）或真人录制“我在”；
2. 转成 16 kHz / 16-bit / mono PCM，约 0.5–0.8 s，约 16–26 KB；
3. 作为 `const int16_t` C 数组嵌入固件，或放入独立小分区/SPIFFS；
   - 32MB Flash 空间充足，第一版直接嵌入最简单；
4. 新增 `voice_wake_ack.c/.h`：
   - `voice_wake_ack_play()`：把 PCM 写入 ES8311 DAC / `voice_output`；
   - 不调用 WebSocket、不调用百度；
5. 唤醒流程改为：

```text
WakeNet 检测到“你好小智”
  -> 本地播放“我在”
  -> 等待播放完成
  -> 清空麦克风队列，丢弃提示音和唤醒词尾部
  -> 再建立 conversation WebSocket
```

这样不会把“我在”上传或识别成用户指令。代价是唤醒后约 0.5–0.8 秒才开始会话，但体验比“唤醒后没反应”好。

### 1.4 回声与 AEC

第一版建议 **先播完提示音、flush 麦克风、再开会话**，不依赖 AEC：

- 提示音不会被上传；
- 不会触发 VAD；
- 不需要额外的参考通道。

后续如果要把“我在”和会话启动重叠，必须使用 AEC 参考；否则麦克风会拾取提示音，服务端可能把它当成用户说话。AEC 方案见第 2.5 节。

### 1.5 Flash 资源

- 16 kHz × 16-bit × 0.8 s = 25.6 KB；
- 可放在应用固件常量区，或使用独立 SPIFFS/小分区；
- 若后续需要多句提示音，建议使用独立资源分区，不要把大量音频塞进 `.rodata`。

### 1.6 代码落点

| 模块 | 工作 |
|---|---|
| `voice_wake_ack.c/.h`（新增） | 本地提示音资源与播放接口 |
| `voice_codec_board.c`（新板实现） | ES8311 DAC 输出、音量/静音 |
| `voice_output.c` | 复用播放队列；增加本地提示音路径或独立低延迟写入 |
| `voice_service.c` | 唤醒后先播放提示音、flush、再进入 conversation |
| `voice_audio.c` | 播放提示音后清空/丢弃采集队列 |
| `profiles/s3-n32r16v.defaults` | 增加唤醒应答开关、提示音资源选择 |

### 1.7 验收

- 断网状态下唤醒，仍能听到“我在”；
- 唤醒后 1 秒内开始本地播放；
- 服务端没有收到“我在”的 ASR 文本；
- 提示音结束后 conversation 正常建立；
- 连续唤醒 10 次，提示音不卡顿、不爆音、不触发看门狗。

## 2. ES7210 + ES8311 + NS4150B 音频板

从器件组合看，这块板很可能是 **ESP32-S3-Korvo-2 或同类音频板**；具体引脚、I2C 地址、参考回采必须以实际板子原理图为准，不能先猜。

### 2.1 器件职责

#### ES7210

- **4 通道音频 ADC**；
- I2S/TDM 输出，24-bit；
- 内置 PGA、MICBIAS；
- 适合双麦克风输入；
- 只负责“麦克风 → 数字 I2S”，没有功放输出。

#### ES8311

- **单声道 audio codec**，同时有 ADC 和 DAC；
- I2S 接口，I2C 控制；
- DAC 输出模拟音频，送给 NS4150B；
- 可配置音量、静音、PGA、DRC/EQ 等；
- 本板主要作为 **TTS/音乐 DAC 输出**。

#### NS4150B

- **模拟输入的 3W D 类功放**；
- 不是 DAC，不能直接接 I2S；
- 输入来自 ES8311 模拟输出；
- 输出接 4Ω/8Ω 喇叭；
- 3.3–5V 供电，5V 才能发挥 3W；有 shutdown/mute 时用于防爆音。

### 2.2 信号链

```text
双麦克风
  -> ES7210 ADC
  -> I2S 数据 -> ESP32-S3

ESP32-S3
  -> I2S 数据 -> ES8311 DAC
  -> 模拟音频 -> NS4150B
  -> 喇叭
```

### 2.3 供电与接线

- **ES7210/ES8311 是 3.3V 器件**；板上若有 LDO，可从 5V 输入降压；若没有，必须分别供 3.3V，不能直接上 5V。
- **NS4150B 建议 5V**，3W 输出；3.3V 也能响但功率小。
- 共地；功放电源要独立去耦，避免 USB/电机噪声。
- 喇叭 4Ω/8Ω、3W 级别；先小音量测试，防止削顶/破音。
- 若有 `SHDN`/`MUTE`，初始化时先静音，配置完再开，减少上电爆音。

### 2.4 与 ESP32-S3 的连接

需要从原理图确认：

- I2S BCLK / WS / MCLK；
- ES7210 SDOUT → S3 DIN；
- S3 DOUT → ES8311 SDIN；
- ES7210/ES8311 的 I2C SCL/SDA、地址；
- 两个 codec 的 reset/power enable；
- NS4150B shutdown/mute；
- 喇叭正负极。

典型做法：S3 做 I2S master，ES7210 与 ES8311 共享 BCLK/WS/MCLK，数据线分开；I2C 分别配置两个 codec。

### 2.5 AEC 参考通道

这是这块板最关键的检查点：

- ES7210 有 4 个 ADC 通道；如果板子把 **功放输出/ES8311 输出衰减后回采**到其中一个 ADC 通道，就能做硬件 AEC 参考；
- 如果没有硬件回采，只能用 ES8311 的 ADC（前提是板上已把输出回采到它）或软件参考（把下发的 TTS PCM 喂给 AFE）；
- 软件参考必须实测，不能直接宣称可靠；
- 没有 AEC 时，只能维持半双工，不能实现可靠打断。

### 2.6 软件接入顺序

1. I2C 扫描，确认 ES7210/ES8311 地址和芯片 ID；
2. ES8311 DAC 输出测试音，NS4150B 小音量出声；
3. ES7210 双麦克风采集，测 RMS/通道映射；
4. 配 AEC 参考：ES7210 mic + reference 两通道，AFE 改为 `MR` 或对应模式；
5. 实现 `voice_codec_board.c`：输入/输出/参考/音量/静音；
6. 加 `voice_wake_ack` 本地“我在”提示；
7. 再测半双工长会话，最后才做打断/AEC。

### 2.7 需要提供的信息

1. 板子完整型号/商品链接/原理图；
2. I2S、I2C、MCLK、reset、功放 shutdown 的丝印或引脚；
3. 麦克风数量、喇叭阻抗/功率；
4. 是否存在 AEC 回采参考（功放输出回采到 ES7210/ES8311）。

拿到这些信息后再实现 `voice_codec_board.c`，不要先猜引脚或电源。

## 3. 与当前语音会话的关系

- 当前 S3 仍使用 ICS43434 单麦、无输出；长会话已经可用，但 TTS 只在 Mac 上播放（测试期）或完全静音。
- 新板接入后：
  - 输入：ES7210 → AFE；
  - 输出：ES8311 → NS4150B；
  - 本地提示音：`voice_wake_ack` → ES8311；
  - AEC 参考：ES7210 参考通道/软件参考；
  - 设备端 TTS：pyserver `speak` 1 KB 分片 → `voice_output` 重组 → ES8311。
- 本地“我在”不改变 pyserver 协议；pyserver 仍只负责会话/LLM/TTS 文本和音频。

## 4. 用户提供的板子规格与接口（2026-11-11 补充）

说明书描述：双麦克风、AEC 回声消除、对话实时打断、高信噪比 SNR、3W 音频功放、codec 音频开发；音频芯片 ES7210 + ES8311，功放 NS4150B，VCC/GND 推荐 5V，通信 I2C + I2S。

### 4.1 接口含义

| 板子丝印 | 含义 | 方向/接法 |
|---|---|---|
| SDA/SCL | I2C 控制 | 接 S3 I2C，3.3V 逻辑；先扫描地址 |
| MCK | Master clock | S3 I2S 输出 MCLK（16 kHz 常用 256×fs = 4.096 MHz） |
| BCK | Bit clock | S3 I2S BCLK |
| WS | 声道选择/LRCLK | S3 I2S WS；默认 mono 时要改 codec 配置才能用双麦/参考 |
| DI | data input | **按板子视角**是数据输入到 ES8311 DAC，接 S3 I2S DOUT |
| DO | data output | **按板子视角**是 ES7210 ADC 数据输出，接 S3 I2S DIN |
| EN | NS4150B 功放使能 | 高电平开、低电平关；可接 3.3V 常开，或 S3 GPIO 控制 |

⚠️ DI/DO 的“输入/输出”可能按板子或按 ESP32 视角标注。接线前用原理图/万用表确认；接反不会烧，但不会有声音/录音。  
⚠️ 所有 I2C/I2S 逻辑是 3.3V；VCC 5V 只进板子的电源/LDO，不要把 5V 加到 SDA/SCL 或 codec 的 3.3V 引脚。

### 4.2 建议的 S3 GPIO（待按你的实际板子确认）

当前 S3 旧麦克风占用 GPIO12/13/14，UART1 用 4/5；S3 WROOM-2 的 26–37 是 Flash/PSRAM，不能用作外设。可先按下面这组规划，**不要直接照抄烧录**，先确认板子和现有接线：

| 信号 | 建议 GPIO | 说明 |
|---|---:|---|
| I2C SDA | 8 | 3.3V 上拉 |
| I2C SCL | 9 | 3.3V 上拉 |
| I2S MCK | 15 | S3 输出 MCLK |
| I2S BCK | 16 | S3 输出 |
| I2S WS | 17 | S3 输出 |
| I2S DOUT → 板 DI | 18 | S3 发 ES8311 DAC 数据 |
| I2S DIN ← 板 DO | 21 | ES7210 ADC 数据进 S3 |
| NS4150B EN | 7 | 高开低关；加下拉，初始化完成后再拉高 |

避开：GPIO19/20（USB）、43/44（UART0 console）、26–37（Flash/PSRAM）、0/3/45/46（strapping）、4/5（UART1）。

### 4.3 供电和功放

- 推荐 **VCC=5V** 给板子；用万用表确认板上 3.3V 测试点正常，再接 codec 逻辑。
- NS4150B 的 3W 输出需要足够电流和去耦；不要从 S3 的 3.3V 稳压器给功放供电。
- 喇叭 4Ω/8Ω、3W；先小音量，避免削顶和电流冲击。
- EN 高电平打开功放；如果常接 3.3V，初始化/关机时不能静音；建议 GPIO 控制，初始化完成后拉高，关机/重启前拉低。
- I2C 上拉只在 3.3V；不要上拉到 5V。

### 4.4 AEC 与“实时打断”的真实边界

- ES7210/ES8311 本身不是 AEC 芯片；“AEC 回声消除”需要 **ESP-SR AFE 的 AEC + 参考通道**。
- 参考通道可能来自：
  1. 板子把 ES8311/NS4150B 输出衰减后回采到 ES7210 的某个 ADC 通道（最佳硬件参考）；
  2. ES8311 的 ADC 已被板上回采（需原理图确认）；
  3. 没有硬件回采时，把下发的 TTS PCM 作为软件参考（必须实测）。
- 没有参考通道时，只能半双工；不能承诺“实时打断”。
- 验证方法：小音量播放一段已知 tone/TTS，同时录 ES7210 各通道；若某通道与播放信号强相关，就是硬件参考。随后用 `afe_config_init("MR", ...)`、`aec_init=true` 做 AEC。

### 4.5 I2C 地址和 codec 配置

- 先 I2C 扫描，不要凭猜：
  - ES7210 常见 7-bit 地址 0x40/0x41/0x42/0x43（由 AD 脚决定）；
  - ES8311 常见 0x18/0x19（由 CE 脚决定）。
- ES7210：双麦 PGA/MICBIAS、采样率、I2S/TDM 通道数、参考通道。
- ES8311：DAC 时钟/格式、音量、静音、MCLK/BCK/WS 从模式。
- S3 做 I2S master，codec 做 slave；共享 MCK/BCK/WS，DI/DO 分开。
- 16 kHz 下建议 MCLK=256×fs=4.096 MHz（以 codec 数据手册为准）。

### 4.6 上板顺序

1. 只接 VCC/GND，测 3.3V 和电流；
2. 接 I2C，扫描 ES7210/ES8311 地址；
3. 接 I2S 输出，EN 拉高，播放小音量测试音；
4. 接 I2S 输入，测双麦 RMS/通道映射；
5. 播 tone + 录各 ADC 通道，确认 AEC 参考；
6. 实现 `voice_codec_board.c`（输入、输出、参考、音量/静音）；
7. 加本地“我在”提示，先播完再开会话；
8. 最后做 AEC/全双工打断。

### 4.7 仍需确认

- 板子完整型号/原理图；
- DI/DO 视角；
- ES7210 输出几通道、是否有参考回采；
- NS4150B EN 是否已有下拉/默认状态；
- 喇叭阻抗/功率、板上 3.3V LDO 能力；
- 你希望 S3 用哪组 GPIO（现有语音/UART 不能冲突）。
