# CodeMyCar 硬件规格与当前接线

更新：2026-11-12。用途：硬件选型、接线和后续 agent 接手时统一查阅。

本文区分**厂家/用户给出的额定规格**、**当前固件配置**和**实机验证**。额定上限不等于本车允许长期运行的工作点；旧文档中的C6、旧麦克风或舵机中位值不能直接套用。

## 2. STM32规格与配置

| 项目 | 值 |
|---|---|
| CPU | Arm Cortex-M7，带FPU/DSP；器件最高550MHz，**本项目250MHz** |
| 内置Flash | STM32H723ZG为1MB |
| SRAM | 器件总计564KB（含4KB备份RAM），不等于全部可作FreeRTOS堆 |
| 外部晶振配置 | HSE 25MHz |
| 总线 | 当前HCLK 250MHz、PCLK1 125MHz |
| 软件 | STM32 HAL + FreeRTOS / CMSIS-RTOS2，tick=1000Hz |
| 主要职责 | 电机闭环、编码器、舵机、IMU、运动安全、INA219测量与电量估算 |
| 下载调试 | ST-LINK / SWD；开发板5V供电入口与GPIO的3.3V逻辑域必须区分 |

器件额定CPU/存储规格参考[ST官方数据手册](https://www.st.com/resource/en/datasheet/stm32h723zg.pdf)；项目时钟依据 `stm32_project/Core/Src/main.c`、`Core/Inc/stm32h7xx_hal_conf.h`。`.ioc`未完整包含后续手写外设配置，应结合源代码及本表核查，不能仅看CubeMX图。

2026-11-13运行优化：默认CPU仍250MHz，I-cache / D-cache开启；UART/LED DMA固定在MPU不可缓存8KiB专区；IMU I²C1采用中断传输。500MHz为可选对照，保持AHB250MHz、APB125MHz和定时器250MHz。任务栈/堆、实机结果和配置见[STM32运行基础交接](stm32_project/Docs/STM32-Runtime-Performance-Handoff-2026-11-13.md)。

### RTOS任务优先级

CMSIS任务优先级数值越大越高；这与NVIC中断优先级的数字规则不同。

| 任务 | 当前优先级 | 电量功能的关系 |
|---|---|---|
| 电机控制、安全监督、运动遥测任务 | `osPriorityHigh` / 40 | 高于电源任务 |
| 命令处理、运动控制任务 | `osPriorityAboveNormal` / 32 | 高于电源任务 |
| IMU、舵机任务 | `osPriorityNormal` / 24 | 高于电源任务 |
| **PowerTask** | **`osPriorityBelowNormal` / 16** | 1536B栈，独占I2C2，约4Hz采样、约1Hz上报 |
| SonarTask、LogTask | `osPriorityBelowNormal` / 16 | 与电源任务同级，仍接受高优先级任务抢占 |

PowerTask与现有代码风格一致，分为Module寄存器驱动、Service计算/打包、Task采样编排。传输有超时，故障2秒重试，有界清总线，不在运动循环中读电源，也不为此关闭中断；尚未单独测量CPU占用率或任务栈高水位。

## 3. ESP32-S3规格、内存及接线

| 项目 | 当前值 |
|---|---|
| 处理器 | Xtensa LX7双核，240MHz |
| 内部SRAM | 芯片512KB，另有RTC SRAM；实际可用堆小于器件总量 |
| 外部Flash | **32MB Octal Flash**，固件80MHz/DTR配置 |
| PSRAM | **16MB Octal PSRAM**，固件80MHz |
| 无线能力 | 2.4GHz Wi-Fi 802.11b/g/n、Bluetooth LE 5；当前链路主要使用Wi-Fi |
| 主要职责 | UART协议桥接、MQTT、WebSocket音频、离线唤醒、AFE/AEC及设备播放 |
| 开发板连接口 | 标注UART的USB口用于下载/串口；另有原生USB口 |
| 电平 | 外设GPIO为3.3V逻辑；内部Flash/PSRAM的1.8V不等于外设GPIO电平 |

规格依据[Espressif WROOM-2官方手册](https://www.espressif.com/sites/default/files/documentation/esp32-s3-wroom-2_datasheet_en.pdf)、`esp32_project/profiles/s3-n32r16v.defaults`及当前`sdkconfig.s3`。大Flash提升容量，不直接提升CPU性能；PSRAM也不能替代所有内部RAM/DMA/任务栈。

Flash当前分区：factory应用从0x10000开始，6MB；model从0x610000开始，4MB；NVS/PHY保留原偏移，其余Flash预留。当前不是已交付双分区OTA或完整媒体文件系统。

| 信号 | ESP32-S3 GPIO/连接 |
|---|---|
| UART1 TX | GPIO4 → STM32 PA11 |
| UART1 RX | GPIO5 ← STM32 PA12 |
| 音频I2C | GPIO8 SDA、GPIO9 SCL |
| 音频MCLK | GPIO15 |
| 音频BCLK | GPIO16 |
| 音频WS/LRCLK | GPIO17 |
| 音频DOUT | GPIO18 → 板子DO → ES8311 |
| 音频DIN | GPIO21 ← 板子DI ← ES7210 |
| 功放EN控制 | 当前配置PA_GPIO=-1，**固件不控制GPIO7**；EN实物取电以实际接线为准 |
| 原生USB | GPIO19/20，不用于本车音频 |
| UART0调试 | GPIO43/44，不用于STM32控制UART |

不要使用WROOM-2内部Flash/PSRAM已占用或未引出的存储管脚；历史建议接GPIO7控制EN不等于当前实物已经如此接线。音频DI/DO按本板实际为ESP视角，旧文档早期表格方向曾写反，以上采用已验收映射。

### 音频板当前配置

- 整板推荐5V供电，I2C/I2S仍为3.3V逻辑；本轮未重新核查音频板具体5V取电点。
- ES7210当前驱动7位地址0x41（库默认8位地址0x80加0x02，再右移）；ES8311为0x18。INA219在STM32的另一条总线上，地址不冲突，无需为音频板改址。
- 采样16kHz；RX为4-slot/16-bit TDM，TX为32-bit stereo；网络音频为PCM16单声道，每方向原始音频约32KB/s。
- 当前算法取单麦M + 硬件参考R；参考TDM slot1对应物理ADC2/MIC3。**音频板有双麦能力，不代表当前已启用双麦算法。**
- 当前麦克风增益37dB、参考12dB、音量60；离线唤醒“小鸭小鸭”，AEC启用，独立NS和AGC关闭。
- 喇叭4Ω/3W，功放为桥接输出，喇叭负端不是公共GND。

语音边界及未完成项见[语音交接](esp32_project/docs/voice/Voice-Baseline-And-Agent-Handoff-2026-11-12.md)。

## 6. 电池、测量范围与供电拓扑

```text
电池正极 → INA219 VIN+ → R100分流电阻 → VIN− → TB6612主电源正极输入
电池负极 ───────────────────────────────→ TB6612负极 / 公共GND

TB6612板5V稳压输出 → STM32的5V入口 → ESP32的5V入口（用户描述的独立供电拓扑）
当前台架：STM32和ESP32还分别连接电脑USB，可能由USB承担部分逻辑负载。

STM32 3V3 → INA219 VCC；公共GND → INA219 GND
STM32 PB10/PB11 ↔ INA219 SCL/SDA
```

关闭TB6612开关并不保证USB供电的逻辑侧已经断电；本轮接线后已验证通信，但后续改线应断开所有供电。USB与板载5V并存的回灌隔离能力未取得板级原理图确认。

INA219芯片允许0–26V总线、3–5.5V逻辑供电，本车逻辑选3.3V；分流最大档±320mV。[TI数据手册](https://www.ti.com/lit/ds/symlink/ina219.pdf)

**用户确认的R100=0.1Ω，因此满量程电流约±3.2A。这个是ADC测量范围，不是模块连续承流额定值或过流保护阈值。** 分流电阻功率、PCB走线和接线端子能力尚未确认：

| 工况（按电机说明书计算） | 总电机电流 | R100压降 | 分流电阻发热功率I²R |
|---|---|---|---|
| 两只额定电流合计 | 0.72A | 72mV | 约0.052W |
| 3.2A总电流 | 3.2A | 320mV | 1.024W |
| 两只同时堵转 | 6.4A | 640mV，超出当前测量范围 | 4.096W，模块承受能力未证实 |

因此当前模块已证明能通信、读电压和低负载分流信号；**尚不能确认R100版GY-219适合覆盖这台车的全部电流工况**。不要通过堵转来验证量程。若要覆盖约6.4A及余量，应重新选择合适分流阻值/功率和有明确额定能力的测量模块；换成R010虽理论量程提高，也不能仅凭阻值就认定整块板可承受32A。

本次用户确认R100后，硬件CMake presets启用100mΩ。电流公式 `I=分流压降÷0.1Ω`，例如10mV对应0.1A。软件标记表示阻值已配置，不等于经过仪表计量校准。

最新静止验收（双USB连接、电机STOP）：约11.869V、0.014A、0.166W、电量估算81%，R100配置30秒连续上报通过。该电流不代表纯电池供电的全车静态功耗；原始证据见[R100验收](stm32_project/Docs/validation/ina219-2026-11-12/r100-current-30s.json)。

## 7. 电量数据及上报归属

| 数据 | 来源/含义 |
|---|---|
| 负载侧电压 | INA219 VIN−对GND，4mV/LSB |
| 分流压降 | VIN+减VIN−，10µV/LSB，可正可负 |
| 电池端电压 | 负载侧电压加分流压降 |
| 电流 | 分流压降除以已知电阻；当前R100配置100mΩ |
| 功率 | 电池端电压×电流 |
| 平滑电压 | STM32滤波结果，用于减少百分比跳动 |
| 电量百分比 | STM32按通用3S电压曲线插值的估算，不是芯片直接测出的百分比 |
| 附加状态 | 时间戳、有效位、错误码、地址、阻值、上层数据年龄/过期状态 |

```text
INA219 → STM32 PowerTask（约4Hz采集）
       → UART v2 SENSOR帧（约1Hz独立电池帧，payload29字节）
       → ESP32解码JSON，type="battery"
       → MQTT data/DEV_1/sensor
       → pyserver GET /api/v1/devices/DEV_1/status 的 battery
       → 手机页面 / LLM车辆状态工具
```

这是传感器遥测，和轮速共用物理UART与网络链路，但**不混入轮速motion帧，也不等到健康心跳一起发**：

| 数据类别 | UART外层TYPE | MQTT主题 |
|---|---|---|
| 电池/IMU/超声波 | SENSOR=0x01，电池子类型SENSOR_BATTERY=0x05 | `data/DEV_1/sensor` |
| 轮速、运动状态、位姿 | MOTION=0x07 | `data/DEV_1/motion` |
| ESP健康心跳 | ESP自产，通常不经过STM32 | `data/DEV_1/heartbeat`，通常约30秒一次，连接变化可提前 |

注意电池“子类型0x05”与协议外层“HEARTBEAT类型0x05”处于不同字段，不能混淆。外层UART v2帧头、CRC与已有motion布局未改，本次新增电池子类型和ESP32解码、服务端字段。电池帧约37字节/秒（含8字节外层开销），8N1下约占115200波特线速的0.32%，不含其他遥测/日志。

当前百分比先对电压平滑，再按3S曲线查表插值；12.6V附近对应100%，12.0V附近约85%，11.1V附近约40%。**这些只是初始通用估算，不是电压线性除以12.6，也不是经过实物标定的容量百分比。**负载、温度和老化会改变关系。1800mAh用于后续容量模型，不代表现在已实现库仑积分。没有把电量估算当作锂电池保护器。

详细协议、测试和历史异常见[INA219实现交接](stm32_project/Docs/INA219-Battery-Telemetry-Implementation-2026-11-12.md)。

- 待补STM32开发板商品型号/原理图、舵机型号、音频板商品型号/原理图、TB6612模块5V输出额定电流、GY-219分流电阻额定功率和持续承流能力、电池化学体系及倍率/BMS规格。

- 来源优先级：当前实物确认 + 当前固件 + 有条件的验收记录；旧设计建议仅作历史参考。硬件规格页不记录Wi-Fi口令、云API密钥或家庭音频。
