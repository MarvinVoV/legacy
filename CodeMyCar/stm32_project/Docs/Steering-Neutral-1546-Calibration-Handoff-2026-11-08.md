# 舵机中位 1546µs 标定与接手记录

## 最新状态

开发分支 `codex/steering-neutral-1546`，从已 push 的 main/`1608658` 创建。本次统一中位从 1530µs 改为 **1546µs**；主机回归与构建通过，**尚未烧录或完成新中位实车往返验收**。用户电脑中途没电，正准备重新连接 STM32；断电前的空间就绪答复不能直接用于恢复后的运动。

## 选择依据与修改范围

用户仔细观察发现 1530µs 时右前轮仍向右偏。零 RPM 下先大角度左转，再回到待测位置，以减少小幅动作无法克服机械回差的影响：1538µs 仍偏右，1551µs 左调过多，1546µs 用户反馈“这次看着是好了”。读回实际 PWM 后记录上述数值；不是把 API 曲率换算值当成真实轮角。

将 `steering_lut.h` 的 `STEERING_SERVO_STRAIGHT_US` 设为1546。生产 LUT 零曲率、MotionService 的 STOP/正常 GOAL 收尾、启动安全脉冲原本已共享这一常量，因此一起生效。保持原始标定表、安全脉宽范围、控制增益、RPM 契约和正常完成门禁不变；更新相关脉宽及原始舵机角预期测试。

静态外观回正不是带载直行精度证明，也不能据此认定原有毫米级偏移全部来自中位。平滑服务存在死区，临时 API 校准请求的目标脉宽与实际读回值可能相差1–2µs；正式 STOP 使用立即定位路径，应实测确认1546。

## 恢复后待做

1. 检查 USB/ST-LINK、MQTT、pyserver 与设备当前状态，确认没有旧校准保持脚本继续发送。临时脚本已停止；最后旧镜像确认 STOP204，断电后状态须重新读取。
2. 电机保持停止，烧录上述镜像并读回验证。先验证停车时 TIM2 CCR1=1546，TIM3 CCR1/CCR2=0/0，并确认新固件/设备在线及双轮零速。不要额外增加未确认的运动。
3. 重新取得用户起点标记、前方1m及停车余量、返回路径与USB线就绪答复，然后10cm/s前进1m、停车、倒回1m，保留独立超时 STOP 和最终停车确认；不能因旧答复已就绪而断电后直接开车。
4. 与此前同一标点方案比较并记录用户反馈；尚未证明真实横偏改善，不合并/推送新候选冒充已实车验收。当前 main 已 push 的阶段基线仍是1530µs版本。
