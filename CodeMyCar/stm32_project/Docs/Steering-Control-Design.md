# 转向控制方案：曲率接口 + 实测标定 LUT

> 版本：v1（设计定稿，代码未改）
> 日期：2026-11-03
> 状态：**已实施并刷写**，静态 round-trip 与地面直行标定完成（见 13.1/13.2）；
> 遗留：舵机臂机械复位、定曲率绕圆标定、IMU 航向闭环
> 相关文档：`MotionServiceDoc.md`、`Motor-Control-Tuning.md`、
> `Landing-Test-Issues-2026-11-01.md`、`esp32_project/docs/cmd-mapping.md`

## 0. 结论摘要

- 上层控制量从**归一化百分比 `steer_percent`** 改为**曲率 `curvature_1pm`（1/m，右正）**。
- STM32 内部：`κ → δ = atan(L·κ) → 实测 LUT → 舵机脉宽`，机械非线性、左右不对称、两端饱和全部由 LUT 吸收。
- 标定基准：**1500 µs = 前轮正中、直行**（舵机已重新机械校准，无软件偏移）。
- 可用范围：`|κ| ≤ 3.770 1/m`，对应 `R_min = 265 mm`、等效转角 ±28.5°（取弱侧左转）。
- 右侧机械能力更强（实测 +38.5°，κ=5.52 1/m），本方案**不作为 API 范围暴露**，仅在 LUT 中保留。

## 1. 背景

### 1.1 现状问题

| 问题 | 表现 |
|---|---|
| 接口无物理含义 | `steer_percent` 只约定 0=居中、±100=满，没有单位 |
| 执行器映射是拍脑袋的 | `steering_map.c` 用 0%/±100% 两个锚点线性插值到舵机偏移 |
| 模型与执行器脱节 | 运动学硬编码"100% = 25°"，与实际转角无关 |
| 机械非线性 | 实测脉宽→转角两端饱和、中段灵敏 |
| 左右不对称 | 右侧可达 38.5°，左侧只有 28.5° |

后果：GOAL/DRIVE 按 25° 规划，车实际转得更急（右侧最多 38.5°），落地测试里转弯半径与预期不符、
直行漂移都需要靠"中位补偿百分比"打补丁——而这个补丁又随机械拆装失效。

### 1.2 目标

1. 上层只表达**曲率**（轨迹量），不需要知道轴距、舵机、连杆。
2. 执行器映射来自**实测标定**，可复现、可重新标定。
3. 规划模型与执行器使用同一套数值，不再有第二套假设。

## 3. 标定数据（2026-11-03）

### 3.1 采集方法

- 舵机信号线直接接 Arduino UNO R4 的 `A0`，软件产生 50 Hz、500–2500 µs 脉宽。

## 4. 数据分析

### 4.1 单调性

δ_eq 随脉宽严格单调递减，可直接作为单值 LUT 的索引（13 点全部通过）。

### 4.2 灵敏度分布（° / µs）

| 区间 | 灵敏度 | 说明 |
|---|---:|---|
| 950–1030 | 0.069 | 接近右极限 |
| 1030–1150 | 0.071 | |
| **1150–1250** | **0.110** | 最灵敏（可能含测量噪声） |
| 1250–1350 | 0.035 | 局部平坦 |
| 1350–1500 | 0.067 | 中心区 |
| 1500–1650 | 0.053 | 中心区 |
| 1650–1750 | 0.035 | |
| 1750–1850 | 0.045 | |
| 1850–1950 | 0.035 | |
| 1950–2050 | 0.045 | |
| 2050–2150 | 0.030 | |
| **2150–2250** | **0.015** | 接近左极限，明显饱和 |

结论：**不能用线性映射**。两端各有一段"100 µs 只换 1–3°"的死区，线性映射会把分辨率浪费在那里，
同时让中心区的实际角度与命令不符。

### 4.3 Ackermann 一致性检查

用 `L = 144 mm`、`T = 167 mm` 从左右轮角分别反推转弯半径 `R`：

| 脉宽 | 转向 | 由内轮推 R | 由外轮推 R | 一致性 |
|---:|---|---:|---:|---|
| 950 µs | 右 | 261 mm（右轮 39°） | 101 mm（左轮 38°） | **矛盾（2.6×）** |
| 2150 µs | 左 | 305 mm（左轮 33°） | 292 mm（右轮 21°） | 一致（4%） |

解读：

- 右转时两轮几乎平行（39°/38°），不符合阿克曼关系 → 右侧连杆近似**平行转向**；
- 左转时内轮明显大于外轮（33°/21°）→ 左侧接近**阿克曼几何**。

因此**不能**用阿克曼公式从两轮角反推等效角（右侧会得到 44.7° 这种不可能的值）。
本方案采用**两轮角平均**作为等效转角，它等价于对单轨模型的最小二乘拟合；对平行转向机构是最稳健的估计。

### 4.4 不对称

右侧有效行程 38.5° / 550 µs，左侧 28.5° / 750 µs。左侧脉宽行程更长但转角更小——与"舵机轴偏左、
左半连杆短、力臂效率低"的机械描述一致。两侧必须在 LUT 中分别表达，不能镜像。

## 5. 接口设计：曲率 κ

### 5.1 为什么是曲率

| 候选 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 百分比 `steer_percent` | 简单 | **无物理含义**，每层都要重新解释 | 淘汰 |
| 等效转角 `δ` | 直观、直接对应 LUT 索引 | 依赖轴距；换车即失效；上层要做几何换算 | 内部量 |
| **曲率 `κ`（1/m）** | 轨迹量；与轴距无关；`κ=Δθ/s`；直接进自行车模型 | 直行附近 1/R 数值大 | **采用** |

`κ = tan(δ) / L`，`R = 1/κ`。上层发 `κ`，STM32 自己转成 `δ` 再查表；轴距、连杆、舵机全部封装在 STM32。

### 5.2 符号与范围

- 符号：**右转为正**，左转为负，直行为 0（与 `turn_ddeg` 的约定一致）。
- 可用范围（左右对称，取弱侧）：

```
κ_max  = tan(28.5°) / 0.144 m = 3.770 1/m
R_min  = 1 / κ_max            = 265 mm
```

- 物理上限：右侧 `tan(38.5°)/0.144 = 5.524 1/m`（R=181 mm），**不通过 API 暴露**，LUT 中保留。
  理由：曲率是几何量，范围必须左右一致，否则同一个 `κ=4` 在左转时无效、右转时有效，
  对上层策略是不可预期的。若将来需要更大右转能力，应先把机械/标定做到对称。

### 5.3 与各模式的关系

| 模式 | 转向来源 | 说明 |
|---|---|---|
| ESTOP / STOP | `κ=0` | 经 LUT 得 1500 µs，前轮朝前 |
| DIRECT | API `curvature_1pm` | 左右轮 RPM 保持原语义（调试用） |
| DIFFERENTIAL | `κ=0` | 舵机回中；`v=0` 即原地旋转 |
| DRIVE | API `curvature_1pm` | `δ=atan(Lκ)` 后按 `R=L/tanδ` 算内外轮速差（减少搓胎） |
| GOAL | 规划器内部 | 圆弧段 `κ = Δθ / s`；`distance=0 && turn≠0` 仍拒绝 pivot |

### 5.4 数值接口

| 层 | 形式 | 单位/精度 |
|---|---|---|
| MQTT/HTTP JSON | `curvature_1pm: float` | 1/m，范围 `-3.77..3.77` |
| 二进制 payload | `int16 curvatureMilli` | 0.001 1/m，`-3770..3770` |
| STM32 内部 | `float curvature` | 1/m → `δ` → LUT |

直行是精确的 `0`；`0.001 1/m` 的分辨率对应最小转弯半径 1000 m 的弧，远超本车需要。

## 6. 协议变更（不兼容，两端同时升级）

| 位置 | 现在 | 改为 |
|---|---|---|
| pyserver `MotionParams` | `steer_percent: int (-100..100)` | `curvature_1pm: float (-3.77..3.77)` |
| pyserver `agent_min_turn_radius_mm` | 309 | **265** |
| ESP32 `bridge_codec.c` | `steer_percent` → 0.1% int16 | `curvature_1pm` → 0.001 1/m int16 |
| STM32 `DirectCtrlParam` | `int16_t steerPercent` | `int16_t curvatureMilli` |
| STM32 `DriveCtrlParam` | `int16_t steerPercent` | `int16_t curvatureMilli` |
| `motion_service.h` `MotionTarget` | `float steerPercent` | `float curvature1pm` |

保持不变的：

- 帧格式（`MAGIC|TYPE|SEQ|FLAGS|LEN|PAYLOAD|CRC16`）、9 字节 `ControlCmd`、模式枚举、ACK 语义；
- 500 ms 命令租约、GOAL 语义、`turn_ddeg`/`distance_mm`/`speed_mm_s`；
- 参数仍然是 `int16`，只是**单位含义变了**：从 0.1% 变成 0.001 1/m。

拒绝规则（沿用删除 `steer_angle` 时的做法）：

- 字段缺失或为 `null` → 整条命令拒绝（不落到默认值）；
- `|κ| > 3.77` → pyserver 直接 422；ESP32 与 STM32 各自再次校验，返回 `ACK=2`（无效参数）；
- 非有限值（`NaN`/`Inf`）在 STM32 解码后拒绝。

> 旧固件 + 新 pyserver（或反之）会得到无 ACK/参数错误，**不允许混用**。

## 7. STM32 实现

### 7.1 数据流

```
curvatureMilli (int16, 0.001 1/m)
   ↓ 校验 + 限幅 |κ| ≤ 3.770
δ = atan(L·κ)                (L = 0.144 m，内部量)
   ↓ 分段线性 LUT（13 点，按 δ 索引）
pulse_us
   ↓ raw = (1500 − pulse) × 0.09
raw_offset_deg
   ↓ servo_angle = 90 − raw（符号约定不变）
ServoDriver（保留现有加速度限制）
```

### 7.2 LUT 定义

新建 `steering_lut.c/.h` 取代 `steering_map.c/.h`（语义已完全不同，不复用旧文件名）：

```c
typedef struct { float angleDeg; float pulseUs; } SteerLutPoint;

static const SteerLutPoint kSteerLut[] = {
    { -28.5f, 2250.0f }, { -27.0f, 2150.0f }, { -24.0f, 2050.0f },
    { -19.5f, 1950.0f }, { -16.0f, 1850.0f }, { -11.5f, 1750.0f },
    {  -8.0f, 1650.0f }, {   0.0f, 1500.0f }, {  10.0f, 1350.0f },
    {  13.5f, 1250.0f }, {  24.5f, 1150.0f }, {  33.0f, 1030.0f },
    {  38.5f,  950.0f },
};
#define STEER_KAPPA_MAX_1PM  (3.770f)
#define STEER_ANGLE_MAX_DEG  (28.5f)
#define STEER_SERVO_CENTER_US (1500.0f)
#define STEER_SERVO_US_PER_DEG (2000.0f / 180.0f)   /* 500..2500us <-> 0..180deg */

/* 装配偏移（2026-11-04）：舵机臂跳齿，kappa=0 需输出 1540us；机械复位后改回 0 */
#define STEER_PULSE_OFFSET_US    (40.0f)
#define STEER_PULSE_SAFE_MIN_US  (950.0f)
#define STEER_PULSE_SAFE_MAX_US  (2250.0f)
```

- 表按 `angleDeg` 升序、`pulseUs` 降序，host 测试 `steering_lut_test.c` 逐点检查单调性；
- 表带版本号与 CRC（写在注释与 `steering_lut_version()` 中），便于与标定报告对应；
- 段落线性插值，端点外**不接受**（`|δ| > 38.5°` 返回 false，由上层限幅保证不发生）；
- `κ=0` → `δ=0` → 1500 µs → raw 0 → 舵机 90°，无需任何"中位补偿"。

### 7.3 需要修改的常量

| 常量 | 现在 | 改为 | 说明 |
|---|---:|---:|---|
| `minTurnRadiusMM` | 308.8 | **265.0** | `L / tan(28.5°)` |
| `maxSteerAngleDeg` | 25.0 | **28.5** | GOAL 钳位上限（对称，取弱侧） |
| `trackWidthMM` | 167.0 | **163.0** | 2026-11-03 实测（前后一致）；影响内外轮差速与航向积分（约 2.4%），不改会让 90° 转向少算约 2° |

GOAL 里的钳位分支（`motion_goal.c`）逻辑不变，只是数值从 25° 变成 28.5°。

### 7.4 故障与回中

- ESTOP / 租约超时 / GOAL blocked / 任务失联：与现在一致，命令 `κ=0`，舵机回 1500 µs；
- LUT 查询失败（数值越界、非有限）：按参数错误拒绝命令，不改变当前舵机输出；
- 舵机加速度限制沿用 `ServoDriver` 现有实现（换向不会瞬间跳变）。

## 10. 风险与后续

| 风险 | 现状 | 对策 |
|---|---|---|
| 回差未标定 | 本次数据是单向（由中心到端点） | 后续双向扫描，做 `approach_direction` 双 LUT |
| 中心区精度 | 角度太小、纸面难测，靠插值 | 直行偏差若超标，再用驱动实测反推微调 |
| 打滑 | 落地实测半径大于几何预测（±50% 时 R≈942/2063 mm vs 名义 650） | 低速下可接受；高速另做动态标定 |
| 右侧余量 | 38.5° 能力未暴露 | 将来机械对称化后一并放开 |
| 机械极限未复核 | 927/2313 µs 是校准前测的 | 下次上电先用小步扫描确认安全 ±限位 |
| 温度/电压漂移 | 未测 | 差异明显时在低温/低电量下复测 |
| 机械再变动 | 舵盘齿位、拉杆长度变化 | 必须重跑第 3 节流程并更新 LUT 版本 |

本方案**不做**：曲率闭环（视觉/IMU 反馈）、ArUco 自动标定、回差补偿。这些留作后续迭代。

### 13.1 刷写与 round-trip（2026-11-03 晚）

两块板均已刷入本次构建（`stm32_build=e3dcb5a379bb`，dirty，改动未提交）：
STM32 用 `STM32_Programmer_CLI`，ESP32 用 `esptool`（CP2102 口 `/dev/cu.usbserial-10`）。

发 κ 后读 TIM2 CCR1（1 tick = 1 µs）：

| κ (1/m) | 期望脉宽 | 实测 CCR1 |
|---:|---:|---:|
| 0 | 1500.0 | 1500 (0x5DC) |
| +1.0 | 1377.1 | 1377 (0x561) |
| −1.0 | 1655.6 | 1656 (0x678) |
| +3.77 | 1093.6 | 1093 (0x445) |
| −3.77 | 2249.8 | 2250 (0x8CA) |

肉眼确认：`+3.77` 右满、`−3.77` 左满，两侧均有可见机械余量。
越界 `κ=4.0` 与已删除字段 `steer_percent` / `steer_angle` 均返回 422。

**踩坑记录**：`STM32_Programmer_CLI -c port=SWD` 连接时会**复位 MCU**，此时读 TIM2
是未初始化的 0（会误判成固件问题）。读运行中的寄存器必须加 **`mode=hotplug`**。

### 13.2 地面直行标定与机械偏移补偿（2026-11-04）

撞车后 **舵机臂跳齿**：`κ=0`（1500 µs）时前轮明显偏右。用地面直行测试（DIRECT 29/29 RPM、
约 0.65 m、固定起点）反推真实中位——悬空状态下的"漂移"是左右轮编码器差积分，不能用于标定。

**中位扫描（转向脉冲 → 航向漂移率）**

| 转向脉宽 | 漂移率 | 说明 |
|---:|---:|---|
| 1500 µs | −8.4 °/m | 明显右偏 |
| 1533 µs | −2.6 °/m | |
| **1540 µs** | **+0.1 °/m** | **走直** |
| 1600 µs | +16.8 °/m | 明显左偏 |

补偿方式：舵机的"脉宽 → 轴角"仍是线性，舵机臂只是相对轴转了一个固定角度，所以
整条曲线平移 **+40 µs** 即可精确补偿（`STEER_PULSE_OFFSET_US = 40.0f`，见
`steering_lut.c`）。此时 `κ=0 → 1540 µs`，CCR1 实测 `0x604`。

- 表格数据（13 点角度）**不需要重测**：机械特性未变，只是装配零点变了；
- 输出夹在 `[950, 2250] µs`，因此左满由 −28.5° 变为约 −27.6°（牺牲 0.9° 换安全余量）；
- 若重新对中舵机臂使 1500 µs 重新等于直行，把该常量改回 `0` 即可。

**右轮速度补偿重标定**

撞车+重装后右轮由"发涩"变为"偏快"，原 `speedTrimScale = 1.05` 方向已反。地面 2 m
GOAL 直行（0.1 m/s）测得横向偏移：

| `speedTrimScale`（右轮） | 2 m 横向偏移 | 中段最大航向 |
|---:|---:|---:|
| 1.05 | +138 mm（左） | +6.35° |
| 1.00 | −121 mm（右） | −6.07° |
| **1.023** | **−8 / −37 mm** | −1.9° |
| 1.025 | −50 mm | −2.16° |
| 1.03 | +47 mm | +1.89° |

结论：取 **1.023**。同值重复测量的离散约 ±30 mm，说明已达到开环+轮速补偿的噪声底；
继续调参是在追噪声。

**当前结果**：2 m 直行横向偏差 **1–4 cm**（改造前同场地约 14 cm），净航向 < 1°。
残余偏差主要来自前 1 m 的航向偏移（GOAL 只闭环距离和航向，不闭环横向位置），
要根治需要 IMU 航向/横向闭环。
