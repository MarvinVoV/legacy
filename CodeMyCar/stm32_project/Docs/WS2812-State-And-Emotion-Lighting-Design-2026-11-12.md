# WS2812六灯：接线与状态/情绪效果设计

> 2026-11-13后续更新：I/D-cache已开启，DMA改为MPU不可缓存专区，任务优先级也已优化。下文缓存关闭的条目是点灯阶段历史记录，当前配置请读[运行基础交接](STM32-Runtime-Performance-Handoff-2026-11-13.md)。

用户已确认：WS2812、5V、约20cm、6颗灯，已将VCC接TB6612模块5V、信号接PA8、GND共地。用户描述丝印DO→DIN，仍需按实际测试确认控制器接在整条灯带起始DIN而非DOUT。

本文件为设计及点灯阶段交接；完整状态/情绪协议尚未实现，不代表已经完成实机灯效验收。初期口述WS2821已经澄清，该型号与WS2812通信方式不同。

**点灯阶段更新：** 已实现并烧录低亮度Module/Service/LightTask，用户确认“六颗都亮，能看到呼吸”。当前只运行上电红/绿/蓝、逐颗扫描和青绿呼吸；车辆状态/语音/情绪联动仍是下文设计，尚未实现。当前实物直接PA8连接，未记录加装升电平器件；本次成功不等于所有WS2812版本和环境下均符合高电平门限。

## 硬件与资源

- 推荐PA8 / AF1 / TIM1_CH1。当前Core、Application、.ioc未占用PA8，TIM1未使用；不能因启动向量表有TIM1名称就认为已占用。
- 不复用舵机TIM2、电机TIM3、编码器TIM4/TIM5、HAL时基TIM6、超声波保留TIM7。
- 采用TIM1 PWM + DMA，拟用DMA2_Stream0 / TIM1_UP请求；UART4继续使用DMA1_Stream0/1。
- DMA缓存放RAM_D1的.dma_buffer，32字节对齐，发送前按需clean D-cache，不放DMA不可访问的DTCM。DMA活动期间不改发送数组；首版可以单缓冲忙时跳帧，后续按需双缓冲，不积压旧画面。
- 约800kbit/s，6颗RGB共144bit，数据约180µs；低电平锁存初取≥400µs，最终依实物修订版确认。TIM1时钟根据APB2/倍频规则计算，不直接假定CPU频率。
- LightTask建议CMSIS osPriorityLow（8），低于PowerTask16、IMU/舵机24、运动32、电机40；25Hz渲染，固定小内存。不得通过关中断位操作实现时序。

| 灯带端 | 建议连接 |
|---|---|
| VCC | 稳压5V，不能接电池12V或STM32 3V3 |
| GND | 公共地 |
| DIN | PA8 → 5V供电74AHCT125 → 约330Ω串联 → DIN |
| DOUT | 留空，不能代替DIN输入 |

现有用户接线为PA8直接输出3.3V；部分5V WS2812版本不能保证识别此高电平。可靠接法建议74AHCT125或同类TTL兼容升电平缓冲；其/OE拉低、未用输入固定、电源去耦。5V供电的普通74HC125不能据此视作等价。

灯带入口可预留470–1000µF电容及去耦。TB6612的5V输出额定电流未知，不从STM32 3V3取电，不经控制板排针串供额外负载。功耗先按老版RGB每颗满白约60mA预算，6颗约360mA，此数不是实测；首轮亮度约5%，后续通常10–20%，供电能力需独立确认。改线同时断开电池和USB。

## 分层与数据归属

- Modules/LedStrip：像素编码、TIM1/DMA、颜色顺序及驱动状态。
- Services/Lighting：纯计算的状态机、遮罩、动画、平滑、限亮和过期处理，可host测试。
- Tasks/LightTask：低优先级定时更新，不能阻塞运动或抢占运动锁。
- STM32是灯数、接线、安装方向、动画参数、告警和亮度限制的唯一配置源。
- ESP32只提供实际唤醒/聆听/云处理/播放/打断状态；server/agent只发送有界的情绪提示，不发每颗RGB。
- 当前S3的VOICE_PROCESSING包括多个阶段，不能仅据该状态认定正在出声；说话灯要绑定实际播放活动和排空事件。

## 六颗灯与合成优先级

假设横向安装，以车体自身左→右为L0..L5。L0/L5作为边缘提示，中间L1..L4优先表达语音。若实际纵向安装需重新映射，不能仍把半条灯称为物理左/右转向。

从低到高合成：情绪基底 → 语音 → 运动/提示遮罩 → 本地故障。

| 状态 | 建议效果 |
|---|---|
| 待机/平静 | 青绿3–4秒柔和呼吸 |
| 唤醒 | 暖金从中心向两侧一次展开，约0.5秒 |
| 聆听 | 蓝色两侧向中心聚合 |
| 思考/云处理 | 柔紫光点缓慢移动 |
| 实际说话 | 暖白混入少量心情色，亮度跟播放包络 |
| 开心 | 暖金/杏橙稍快呼吸或短双脉冲 |
| 好奇 | 青蓝小光点移动 |
| 安慰/温柔 | 柔桃粉聚拢、长呼吸 |
| 低落 | 低饱和柔蓝慢呼吸，与红色故障区分 |
| 前进 | 边缘低亮绿，中间保留语音/心情 |
| 倒车 | 边缘暖白低频脉冲 |
| 左/右转 | 对应3颗琥珀色从中间向外流水 |
| 制动 | 边缘红色保持约300–500ms；正常停车不永久显示故障 |
| 低电量/上层失联 | 边缘琥珀慢呼吸，保留中间语音 |
| 本地控制故障 | 6颗柔红慢脉冲，覆盖其他层 |

故障始终最高。运动提示冲突时按制动→实际转向→其他提示处理；低电量可在非运动时短窗口显示。情绪不能伪造故障、解除告警或控制电机。未安装/失效超声波不能凭空显示障碍物告警。

转向提示最好以实际舵机/曲率方向为准，倒车不能只看GOAL车头转角符号就推断前轮朝向。6颗装饰灯不等同合规道路灯。

## 渲染算法

每40ms：读取设备快照和未过期提示 → 检测状态边沿 → 计算基底 → 按遮罩覆盖 → 普通过渡平滑 → gamma → 最终限亮/预算 → DMA空闲才发送。

动画用本地单调时间及状态进入时间；重复状态心跳不能重新启动动画。旧帧可丢，不能排成长队。普通切换约120–250ms过渡，故障进入不等待淡入完成。

- 呼吸：b = b_min + (b_max-b_min) × (1-cos(2πt/T))/2；也可用定点三角波/LUT。
- 平滑：x += (target-x) × (1-exp(-dt/τ))，τ可先取120ms。不要用依赖帧数的常数代替dt。
- 流水：按时间移动平滑光斑；转向在相应3个像素中从内向外移动。
- gamma初值约2.2，实物再看低亮台阶；所有状态都经过同一个最终亮度上限。
- 电流预算根据最终RGB和实物灯芯额定电流估算并整体缩放，只是软件预算，不是硬件过流保护。

说话包络取实际播放PCM的RMS，attack约30ms、release约200ms，量化8位level后最多10Hz发送。不能用麦克风音量、网络刚到达的待播PCM或文本字数当成实际出声强度；首版可先做平稳说话呼吸，再接入播放时序。包络300ms过期回退，打断/播放结束退出说话灯。

低电量UI阈值可先用有效SOC≤20%持续5秒，恢复≥25%持续10秒；无效或过期数据不当成0%。该SOC本身是估算，这些阈值不是锂电池保护阈值，不新增断电或自动停车策略。

## 语义协议与Agent（尚未实现）

当前协议外层0x01..0x09已用，可考虑新增VISUAL=0x0A，实施前同步两端解析器和范围测试。不要塞入运动帧，不续租电机，不改变GOAL事务或占用STOP的可靠ACK槽。

事件为voice_state、expression、audio_level、clear；包含版本、bridge_session、独立visual_epoch/event_id、枚举/强度、受限TTL。原有运动seq/lease与灯效分开。

- SESSION拒绝重启前事件；visual_epoch随新会话或取消更新；代内event_id用于去重和拒绝乱序。
- ESP32拒绝过期turn的server情绪，不能在旧故事取消后重放旧心情。
- 每类只保存最新值，固定小mailbox；音量包络覆盖旧值，无可靠重传积压。
- 初始建议语音租约1.5秒、2Hz刷新；情绪3–8秒、硬上限10秒；音量TTL约300ms、最多10Hz。失联和过期自动回本地状态。
- 装饰灯事件不能被旧固件误解为运动命令；灯带失败不得触发电机动作。

Agent可增加本地express_emotion工具，只有calm/happy/curious/comforting/sad、强度0..100、受限duration，不允许指定GPIO/RGB/设备ID/故障等级。无设备反馈时只说提示已接收，不保证已经亮出准确颜色。

不为了灯效每轮强制再请求一次LLM。首版自动表现以语音状态为主，心情默认calm，显著变化或用户明确设置时才调用情绪工具。普通工具调用也可能增加模型往返；后续若需每轮自动情绪，应使用同一次生成的结构化旁路元数据并验证流式TTS过滤和延迟，不能把隐藏标签朗读出来。

## 实施与验收

1. 低亮度全灭/红/绿/蓝、逐颗定位，确认6个独立像素、颜色顺序及DIN方向。
2. STM32本地待机/运动/故障/电量，核对STOP、IMU与电源采样不受影响。
3. 接ESP32实际语音状态，测试打断、结束、断网及重连降级。
4. 最后加入有界情绪及播放包络，并测首声延迟、UART负载。
5. host测编码位序/波形计数、遮罩、TTL、乱序/重启、缺测电量、方向反转、限亮及DMA所有权；实机确认色彩/亮度/时序、电源、复位全灭。

本次对话的预览只是效果模拟，不连接车辆，不代表烧录结果或实际亮度。

## 当前实现、异常与验收记录

- 已新增Modules/LedStrip、Services/Lighting、Tasks/LightTask；LightTask优先级Low/8、栈1536B。当前采用固定1920B单DMA数组，放RAM_D1且32字节对齐；仅空闲时编码，忙时跳帧，数组不被运行中的DMA和CPU同时修改。
- 250MHz TIM1时钟下，ARR=312、0位95ticks、1位188ticks，约1.252µs/bit；GRB/MSB优先，帧后322个低电平周期。使用更新事件DMA与CCR预装载，启动前低电平，完整保留首尾像素位。
- 开机约0.3秒灭，红/绿/蓝各1秒，6颗依次亮各0.4秒，最后4秒周期青绿呼吸。各通道最大12/255，单颗白光扫描为8/255；尚未开放上层设置亮度或命令。
- 新增host/run_lighting.sh，验证GRB/MSB、首尾数据、低电平锁存、缓存容量、启动序列和亮度上限；集成进host/run.sh。完整STM32 host回归及ARM NoSonar构建通过。
- 第一版烧录出现STM32启动HardFault，未运行到LightTask：异常栈PC位于UART的SCB_CleanInvalidateDCache_by_Addr，CFSR=0x400、HFSR=0x40000000；CCR=0x40200，D-cache未启用。新增DMA数组改变了UART DMA缓存位置，暴露原先无条件cache维护的启动问题。不能把这次全黑/STOP超时归因于用户接线。
- 已给UART RX准备/RX完成/TX准备的cache操作加DC使能位检查；没有主动启用I-cache/D-cache，也没有更改UART协议或指令租约。修复后实机启动，LED DMA完成106→213帧且errors=0；IMU数据新鲜、电池测量正常、STOP seq8确认。
- SWD复核：当前CCR仍0x00040200，DC/IC均关闭，CFSR/HFSR为0。只读内存寄存器检查未修改缓存配置。需要开启缓存时应另做缓存一致性和冷/热启动测试，不能把保护条件误称为“已开启缓存优化”。
- 用户确认六颗全部点亮并可见呼吸。尚未独立确认每一段红/绿/蓝颜色顺序、量测波形/5V电压、长期稳定性或实际灯带电流。DMA计数成功不能替代光学确认。
- 灯带持续输出期间的30秒无运动回归通过：29帧电池数据、最大间隔1.304秒，电压11.849–11.853V、电池侧电流0.016–0.018A，IMU保持新鲜、mode0/零速/无fault，STOP seq9→10均确认。两板仍有USB供电，不能将这几个毫安差值精确当作灯带耗电。

实机证据见[启动与DMA/STOP](validation/ws2812-2026-11-12/bringup-after-cache-guard.json)、[灯带运行中的电源回归](validation/ws2812-2026-11-12/power-regression-30s.json)、[部署镜像标识](validation/ws2812-2026-11-12/deployed-manifest.json)。代码在开发分支，尚未自动合并/推送；未改ESP32固件，本轮灯带基础驱动只需烧录STM32。
