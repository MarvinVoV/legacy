## 1. 复核结论

本次修复有实际进展：同方向动态舵机目标保速、立即命令取消旧轨迹、双轮同比限速、DIRECT 直行判定、从零状态开始的倒车方向、Disable 后参考重捕获及常规航向遥测范围已得到改善。

但不能接受“报告列出的已修复项均已正确闭环”这一结论。仍存在安全制动状态不一致、IMU 发布机制与高优先级读取冲突、GOAL 几何边界漏限幅、异常数据健康标志失效等问题。原 STOP 竞争及共享事务竞争也仍未修复。

特别需要先处理：

1. STOP 旧指令覆盖与制动失败后的真实停车保障；
2. 近场判挡与解除制动互相矛盾；
3. IMU 快照竞争不应清掉航向参考，异常数据应立即失效；
4. GOAL 在进入航向限幅之前就可能映射失败；
5. 正反向切换不能携带错误符号的积分。

本文“已复现”指 host 直接调用当前产品函数；“代码确认”指从调用链和状态分支可确定，尚未证明真机触发频率。修复说明中的“已刷入 STM32、IMU 100 Hz”属于原报告记录，本次未重新连接硬件核验。

## 3. 仍有缺陷的修复项与新增问题

### RR-01 / P1：近场快判与解除刹车可同时成立

来源：原 CTRL-07；本次近场快判新增的状态一致性缺口。已复现。

位置：`Application/Services/Safety/Src/safety_service.c:145–163、200–231`；`motion_service.c:681–716、750–754`。

窗口先填满5次100 cm，再输入一次5 cm：

```text
distanceCm=100, fastBlocked=1
safety_channel_blocked()=true
safety_channel_clear(16)=true
safety_governor_apply() 返回 scale=1.00
```

blocked 使用 fastBlocked，clear 只看中值。MotionTask 先进入制动，下一周期因 clear 为真解除并下发运动目标，再下一周期重新制动。在窗口淘汰近场样本前，可能每5 ms切换一次制动与驱动。该快判不能按现状验收。

建议：使用一次不可变安全快照生成统一决策；释放条件至少要求新鲜有效且无 fastBlocked/fault，再叠加迟滞。必须覆盖“单个近场样本、中值仍远、连续多个控制周期”的测试。

### RR-02 / P1：制动失败后仍认为已制动，失败车轮不再重试

来源：原 CTRL-03，部分修复；代码确认。

位置：`motor_service.c:240–273`；`motion_service.c:696–706、750–754`。

brakeAll 某轮锁超时会返回错误，但调用方仅打印日志，仍无条件置 safetyBraked=true。后续保持制动分支不再调用 brakeAll，且不下发任何电机目标；未制动车轮可能继续保留先前驱动。

另：brakeAll 遇到未初始化轮子直接 continue，未设置 all_ok=false，仍可能返回成功。stop_actuators 的 emergencyStop 返回值仍被忽略。

建议：区分“请求制动”和“制动已提交成功”，逐轮保存执行结果；失败触发 inhibit/故障锁存和重试，不能用日志代替停车。与 STOP 竞争统一解决，但不必等整套重构才做失败闭环。

### RR-03 / P1：IMU seqlock 覆盖耗时 I²C，读竞争被误判为传感器故障

来源：原 IMU-P2-05；修复引入控制可用性问题。host 模拟抢占已复现，真机占空比待测。

位置：`imu_service.c:134–139、215–240`；`motion_service.c:813–821`。

seq 在8次 sh2_service 前置奇数，完成 I²C、解析和姿态计算后才变偶数。传输层包含阻塞式 I²C，写区远大于一次结构体发布。MotionTask 优先级 High，IMU 为 Normal。高优先级读者若在写区中抢占，连续3次重试期间写者无法继续推进，必然读取失败；heading_correct 随即 Disable，清参考角和积分。

探针在 sh2_service stub 中模拟高优先级读取，8/8次 GetSnapshot 失败。真实读者有机会每次都撞上该窗口，导致闭环频繁退出、参考航向被反复捕获，最终“数据在更新，但不能保持原航向”。

此外，Init 的 memset/配置回调、Close 和 ResetYawReference 都不受同一发布协议保护；seq 只有 volatile，缺少明确的编译器/内存顺序保证。模式变化路径仍直接读 yawValid/yawDeg，也绕过快照。

建议：IMU 在私有工作区完成 I²C和计算，只用极短临界区发布完整快照，或采用有明确一致性协议的双缓冲。瞬时发布竞争应保留最后一次仍新鲜的有效快照，不能等同硬故障并清参考。不要把长 I²C 操作放进关中断区。

### RR-04 / P1：异常四元数仍保留 valid，gyro 的异常与停更没有独立健康检查

来源：原 IMU-P1-04、IMU-P2-03；部分修复，已复现。

位置：`imu_service.c:53–68、171–189、229–233`；`motion_service.c:815–830`。

四元数异常时仅提前 return，没有清 yawValid。回调已经更新 lastUpdateMs，快照于是可能显示“新鲜、有效”，内容却是旧 yaw。

探针先产生有效姿态，再令 quatW=NaN 并模拟回调刷新时间戳，得到 `snapshot.valid=1, age=0`。gyroZ=NaN 时仍得到 `snapshot.valid=1`，但 yawRate 非有限。

只有 GRV 更新时间戳；gyro 流单独停止时，只要 GRV 继续到达，角速度闭环仍消费旧 gyro，无200 ms退出。biasValid/标定完成也未纳入快照，未收到 gyro 的情况下 valid 已可为真。

建议：分别记录 lastGrvMs、lastGyroMs，使用成功解算的时间而非收到坏包的时间更新健康状态；异常值立即发布无效状态。角度环与角速度环分别声明所需数据，最终控制计算前校验有限值和标定策略。不能仅靠四元数 norm2 范围推断整组数据健康。

### RR-05 / P1：GOAL 在最终限幅之前就可能映射失败

来源：原 CTRL-01、CTRL-13、IMU-P2-06；代码确认，函数边界已复现。

位置：`motion_service.c:1059–1085`；`motion_goal.c:179–187`；`steering_lut.h`；底盘配置。

GOAL 的 if 条件先调用 curvature_to_raw(curvature)，成功后才调用 heading_correct 进行最终限幅。轴距141 mm、规划转角28.5°时：

```text
angle_to_curvature 成功，κ=3.8507 1/m
curvature_to_raw 失败（全局上限3.770）
```

随后仍走 raw_steer=0 回退，且保留规划器给出的双轮差速。heading_control 的输出限幅根本没有机会执行。可行性准入允许最小半径260 mm，曲率约3.846，也落在该冲突区。

建议：先统一物理可执行曲率并限幅，再同时生成脉宽和双轮目标；StartGoal 用同一可执行边界验证几何，必要时拒绝不可行目标。增加最小半径、最大角度、IMU有效/无效两种条件下的完整 handle_goal 集成测试。

### RR-06 / P2：正反向切换时旧直行积分仍可导致错误方向

来源：原 IMU-P1-01；新建控制器的倒车测试通过，但生命周期不完整。已复现。

位置：`heading_control.c:127–145`。

修复只给当前角度误差乘 sign(v)，积分没有随运动方向变换或清空。探针在 yaw误差+0.6°、前进0.2 m/s持续50 s，积累 integral≈30；同模式改为倒车-0.2 m/s，当前P项应为负，但总修正仍为+0.048，继续向错误方向纠偏。

零速时 sign(v) 默认正，角度环仍积分；速度噪声过零还可能引起P项翻转。

建议：明确运动方向状态及低速迟滞；停止/换向时冻结或重置积分，或先在航向角速度域控制再通过带符号速度转换。新增“先积累积分再换向”的测试，而不只分别初始化前进/倒车。

### RR-07 / P2：最终曲率饱和未参与抗积分饱和

来源：原 CTRL-01、CTRL-10；部分修复，已复现。

位置：`heading_control.c:176–203`。

积分只根据 corrRaw 是否达到±0.30判断是否继续累计，没有感知最终 kappaFf+corr 已被±3.770限幅。探针在 kappaFf=3.770、实际曲率比目标小0.1时运行25 s，rateIntegral≈2.499，内部corr≈0.240，但最终执行曲率始终只能3.770。

减小曲率指令后，这些未真正执行的积分会继续推大转向。lastCorr 也反映内部修正而非实际执行修正。

建议：抗饱和依据最终执行曲率与未限幅曲率的差进行条件积分/回算；诊断分别记录 requestedCorr 和 appliedCorr。低速积分衰减应按dt设定时间常数，而非按调用次数固定乘0.98。

### RR-08 / P2：SafetyChannel 新增字段没有初始化

来源：本次新增字段的初始化遗漏；已复现。

位置：`safety_service.c:82–105`。

init 未初始化 lastValidMs、nearestCm、fastBlocked。生产全局静态对象首次启动因BSS清零暂时掩盖问题，但重初始化仍会保留旧状态；栈对象则可能读到未初始化数据。

探针先令 fastBlocked=1、nearestCm=5、lastValidMs=123，再调用 init；这些值原样保留，空窗口仍判 blocked=true。

建议：完整初始化结构体字段。启动宽限期也应基于通道初始化时间，当前直接比较系统uptime与3000，在后续重初始化及tick回绕时语义不成立。头文件对宽限期返回值的说明与实现亦不一致。

### RR-09 / P2：GOAL 的阻挡中止只看 scale，遗漏新硬停止原因

来源：CTRL-06/07 新逻辑未与事务终态联动；代码确认。

位置：`motion_service.c:670、677–716、719–745`。

近场快判时中值可能仍远，scale=1；SonarTask停更后旧scale也可能为1。硬停止已生效，但 GOAL 仍因scale非零不进入 goalBlocked。预期5 s阻挡中止不会按该原因触发，转而等GOAL硬超时。braked 又抑制堵转检测。

建议：统一生成安全停止原因与 effectiveScale，以真实的“运动输出被禁止”启动GOAL阻挡计时，区分障碍、传感器故障和执行器失败。

### RR-10 / P2：平滑命令仍可能因死区忽略取消旧轨迹

来源：原 CTRL-05 的另一调用入口；已复现。

位置：`servo_service.c:86–94`。

Immediate 的问题已修复，但 Smoothly 仍先按新目标与当前位置差值直接返回。90°向140°移动一拍到90.072°后请求 Smoothly(90)，目标仍保留140°，motionState仍MOVING。

建议：先接受新目标、取消或调整旧轨迹，再决定是否需要物理位移。保留动态目标速度时，也应测试近目标、反向、立即与平滑交替，不只测试同方向远目标。

### RR-11 / P2：初始化重试改善，但配置失败仍被宣告成功

来源：原 IMU-P1-05；部分修复，已故障注入复现。

位置：`imu_service.c:91–112`；`imu_task.c:107–147`。

失败退避重试、无首帧1.5 s重开确已实现。但 callback/config 的返回值仍全部忽略。探针令回调注册和三个配置调用均返回错误，Init 仍返回0、inited=true。

若GRV成功而gyro配置失败，首帧条件被满足且GRV持续刷新，任务不会因为gyro缺失重开。说明“有首帧恢复机制”并不能替代每项配置结果检查。

建议：检查必要配置的返回值、失败清理会话并重试；初始化状态与数据ready状态分开。给gyro/GRV分别设置首帧和运行超时；保留配置错误来源，避免返回舵机错误码。

### RR-12 / P2：GOAL 调用IMU不等于IMU已经参与终态判定

来源：原 IMU-P2-06 功能仅部分完成；代码确认/架构风险。

位置：`motion_service.c:1063–1080、motion_goal_accumulate调用`；`motion_goal.c:71–80、95–105`。

新逻辑确实把IMU修正作用于GOAL舵机和双轮，正向进展应保留。但GOAL航向累计/完成仍只由编码器左右轮程差决定；不能将其描述为融合航向GOAL。轮胎打滑、trim误差、轮速差与真实转角不一致时，IMU修正环和编码器残差规划器可能对同一误差提出相反补偿。

建议：先明确GOAL的角度定义、参考起点和完成依据；IMU与编码器按统一符号和同一事务起点融合，提供两种估计及差异遥测。必须测试圈弧、终点附近、打滑和IMU中断恢复。未完成融合前，报告应明确“IMU参与转向，终态仍编码器判定”。

## 6. 建议修复与验证顺序

1. STOP竞争、逐轮制动失败闭环（CTRL-02、RR-02）；同时修RR-01，消除制动/释放振荡。
2. IMU私有计算+短时间快照发布（RR-03），异常/缺失gyro健康管理（RR-04/11）。
3. GOAL统一几何准入、最终曲率、舵机与轮速输出（RR-05）；明确终态估计（RR-12）。
4. 换向/零速积分生命周期和真实输出抗饱和（RR-06/07）。
5. 安全通道完整初始化、阻挡终态及平滑取消入口（RR-08/09/10）。
6. 集成故障注入通过后再烧录，在启用超声波的配置下做悬空验收，随后低速落地；NoSonar构建不能替代安全链验收。

新增测试应验证安全不变量，而不是仅断言某个字段被设置：

- STOP接受后，任何旧代次目标都无法恢复驱动；
- 任一轮制动失败都不会进入“已成功制动”状态；
- blocked=true时clear必须为false，且连续控制周期不得输出恢复运动目标；
- IMU正常写入期间控制器保持最后有效参考，传感器真实失效时才降级；
- gyro单独停更、坏四元数持续到达、NaN角速度、配置失败均能正确降级；
- GOAL最小半径、最大舵角、IMU有效/无效、终点曲率急增均不触发静默回中；
- 正向积累积分后倒车、正弯直接切反弯、零速长时间等待均不携带错误补偿。
